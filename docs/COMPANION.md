# 独立主动式台灯：当前实现与验证边界

2026-11-14。按用户最新范围：先做独立感知，Margin 联动暂停；先完成架构，再开始真人测试。

## 主链路

```text
MediaPipe 人脸 ──────┐
外设/后续手、坐姿、工作区检测 ─┼─ 带时间、来源、质量的 obs.*
可选 Jev 判断 ───────┘               │
                                     ▼
                         World 时效与单位检查
                        ┌────────────┴─────────────┐
                     Companion                Gestures
                  到来/离开/关怀/活动提醒       手动调光/近灯头引导
                        └────────────┬─────────────┘
                              优先级、冷却、预算
                        ┌────────────┴─────────────┐
                    表达动作候选             连续 Attention / Tracking
                   点头/轻靠近/伸展            朝向 / 灯头位置 IK
                        └────────────┬─────────────┘
                          Lighting 工作照明目标
                                     ▼
                       Player 平滑、速度/加速度限制
                                     ▼
                          Web / Blender / 测试输出
```

`profiles/companion.json` 是默认实验室配置。它关闭 Margin TCP，拒绝 `app.*`，
不发提示请求。原 `proactive` 配置仍保留，两个模式各有合成场景，不互相冒充。

## 用户需求对应到了哪里

| 需求 | 当前代码行为 | 还不能声称什么 |
|---|---|---|
| 人来开启 | `Companion` 要求连续新观测确认到来，问候并缓亮 | 看到脸不等于检测到坐下，更不等于识别睡眠阶段或刚睡醒 |
| 人走熄灯 | 明确未见人持续 30 秒后熄灯；短暂消失保留照明 | 前置相机里的脸消失不一定是人离开房间 |
| 感知中断 | 独立 `sensor_unknown`，保留照明，60 秒故障超时关灯，不自主移动身体 | 不把传感器失联记成真实离开 |
| 久坐提醒 | 有坐姿观测时累计坐姿；站立持续 10 秒重置。无坐姿检测时只累计在桌前时间，用不同理由提醒 | 目前真实输入只有脸，不能把在桌前时长叫已验证久坐 |
| 困倦关怀 | 新观测持续闭眼或张嘴达到时间门槛，触发 `care_check`；180 秒冷却且计入干预预算 | 不是医学疲劳检测、情绪分类或可靠打哈欠分类；眉毛变化不单独触发 |
| 跟随人脸 | `Attention` 按单目位置估计解朝向 IK，8 Hz、位置死区、弹簧平滑 | 深度与相机位姿尚未标定，不能直接用于实体防碰撞 |
| 跟随 iPad/工作区 | `obs.work_target` 的标定坐标优先于人脸；连续跟随和表达动作共用目标 | 尚无自动 iPad 检测器；移动目标目前仅合成输入验证 |
| 桌面上滑亮、下滑暗 | `Gestures` 在稳定进入桌面区域后按桌面轴计算位移增量 | 手部检测、桌面平面标定与写字/指令区分待接入 |
| 靠近、退让、抬高、降低 | 相对手柄控制、近距离退让；离散 beckon/away/raise/lower 只执行一次 gesture_id | 这些是控制契约，不是已训练好的招手识别器 |
| 自适应照明 | 标定工作面 lux 走闭环；手动覆盖；色温目标缓变；无人时关闭 | 摄像头图像亮度不能当 lux，真实冷暖 LED 尚未接入 |

所有门槛在 `profiles/base.json`，是可调初值。普通眨眼不能靠一个缓存帧累积成
持续闭眼；关怀仍受用户“不打扰”、手动接管和干预预算约束。当前新策略不做
学习效果评分，不把默认 engaged 当成真实专注。

## 从 ELEGNT 吸收的设计及工程对应

参考 Apple 原论文：[ELEGNT](https://arxiv.org/html/2501.12493v1)，重点是 §3.2、§3.3、§4.2。
论文把功能目标与表达目标一起考虑；研究演示采用研究者与动画设计师迭代制作的
预录轨迹。它没有提供一个可直接替代我们感知与控制系统的训练模型。

本项目采用以下设计，并把研究启发与自己的算法明确分开：

| 设计 | 本项目的具体处理 |
|---|---|
| 动作先说明意图 | 候选动作包含头先动、身体后跟；到达后留出停顿 |
| 注意力有明确对象 | 工作区、人脸、手动目标三类目标分别仲裁，不持续随机摇头 |
| 距离能传达态度 | 关怀用轻微靠近；手靠近灯头时退让，手动控制优先 |
| 节奏和幅度随场景变化 | 问候小点头；关怀缓慢；活动提醒伸展。预设原语配实时目标 |
| 表达服务于实际功能 | 工作照明独立计算，装饰动作不能把亮度任意覆盖 |
| 互动需要回应与边界 | 暂不打扰取消表达；目标失效保持姿态，不追着人反复提醒 |

现有生成器的 `F + γE` 是我们手写的有限候选评分，**不是 Apple 的原版求解器**。
它组合动作原语，计算 IK 和最小 jerk 插值，再通过有速度、加速度限制的弹簧播放器。
目标失效后保留已到达的姿态，避免弹回旧动画终点。实体避障、力矩反馈、阻抗控制
都还没有实现；近手退让目前只能称位置控制。实际自然感仍待真人观察与调整。

## Jev、JEPA、FastVLM 和 OpenAI 的区别

- [Jev 官方说明](https://docs.typesafe.ai/introduction)：TypeSafe 的结构化判断模型。
  当前提供可选 `sensors/decision.py` 适配器：问两个有界问题，输出 `obs.judgment`。
  API 返回的概率不是台灯领域已验证准确率。
- [Jev 图像能力](https://docs.typesafe.ai/images)：官方仍将图像/Box 标为实验性质。
  本适配器只发送数值和结构化状态，不上传摄像头图片。
- [OpenAI Decisions API](https://developers.openai.com/api/docs/guides/decisions)：
  支持快速类型化判断，是用户提到的同类接口；没有依据断言其发布动机是针对 Jev。
  当前只预留同一归一化观测契约，**未实现或调用 OpenAI provider**。
- [V-JEPA](https://github.com/facebookresearch/vjepa2)：视频表征与预测方向，和 Jev
  不同。当前未安装、未接入，也不把它当成现成的台灯动作或情绪分类器。
- FastVLM：已有可选场景理解适配器，但当前关着；默认由 MediaPipe 提供几何与表情系数。

Jev 是低频旁路：单请求并发、无积压、超时后本地链路继续。返回结果保留**输入观测
时间**，过期结果会被 World 拒绝。它只能帮助抑制不合时宜的关怀，不能输出关节角、
绕过手动优先或凭模型一句话发动动作。没有模型回复时使用本地可解释规则。

独立模式由 `LocalContextSensor` 把本地时间作为 `obs.clock` 写入日志，按日间/晚间目标缓变色温，不依赖 Margin 或核心里的隐式时钟。

默认 `decision.enabled=false`，实验室强制关闭云判断。后续若评测 Jev，通过 CLI
显式启用，使用 `TYPESAFE_API_KEY` 环境变量；需要固定实际模型版本并记录真实延迟、
误触发与漏触发，不能套用厂商的速度数字。当前只做了接口解析与过期结果的离线检查。

## 后续传感器必须满足的契约

```json
{"kind":"obs.occupancy","data":{"present":true,"posture":"seated","quality":0.9}}
{"kind":"obs.work_target","data":{"position":[0.2,-0.3,0.05],"frame":"desk_m","calibrated":true,"quality":0.9}}
{"kind":"obs.hand","data":{"zone":"head","engaged":true,"position":[0.1,-0.1,0.3],"frame":"desk_m","calibrated":true,"command":"beckon","gesture_id":"gesture-7"}}
{"kind":"obs.judgment","data":{"fatigue_cues":0.8,"interruptible":0.9,"model":"model-version","evidence_id":"snapshot-7","observed_at":10}}
```

桌面方向在桌面坐标定义，灯头升降沿 z；不能把摄像头图像 y 的正负直接当成空间升降。
灯头上的相机还需要随关节姿态变换。单个 Mac 前置镜头不保证同时看清脸、整张桌面
和手与灯的距离。先标定再开放距离控制，不用猜测的米制坐标假装已经标定。

## 验证与下一步

架构的合成检查：到来、连续疲劳线索、目标跟随、离开熄灯、再次到来恢复亮度；
单帧不能触发疲劳；坐姿/站姿区分；长期停留提醒预算；过期模型结果拒绝；精确回放。
不打开摄像头、不驱动实体硬件：

```bash
uv run --no-project --python 3.12 --with pytest pytest -q
python3 -m lampkit simulate scenarios/companion.json --set 'body.type="null"'
cd web && npm run build
```

下一阶段才做真实测试：先标定相机与桌面，接手部/坐姿/目标检测，再测感知准确率、
交互延迟与自然感。独立模式做好后再回到 Margin 的学习消息与提示实验。
